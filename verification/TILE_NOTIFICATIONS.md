# タイル・復元通知の検証（v1.2.0）

検証日: 2026-10-09（日本時間）。既存の信頼性修正と対象一覧変更時の退出待ちを維持。

## 変更と最終レビュー

- Applicationの既存Engineをタイル・通知・UIで共有。新しい入口でBinderやDataStoreを直接操作しない。
- タイルは操作前の実値照合、手動ON/OFF、自動所有からの引き継ぎ、未確認状態のアプリ案内、連打の同一要求への集約、ロック解除後の再確認を行う。
- タイルの表示購読を停止時に解除。表示開始の読み込みは退出待ちのgateをリセットしない。
- 通知Actionは非公開Activityのimmutable PendingIntentを直接起動し、Application所有の復元ジョブを待つ。公開MainActivityの旧停止Intent受付は削除。
- 明示的な復元要求をrestoreRequestedに保存し、自動切替をOFFにして手動所有も復元。未完了なら再接続時に要求を引き継ぐ。正常な手動ONは従来通り保持。
- 復元中に受け付けたON要求・待機中のON要求を拒否し、OFF設定の購読やサービス終了処理から明示的な復元を二重に実行しない。
- 復元記録がない場合は実値確認のみ。不正な記録を推測で補正しない。復元完了の読み戻し確認まで記録を残す。
- 復元の失敗・再接続の必要性・未完了・不正な記録を区別して固定IDの専用通知を更新。正常な手動ONや切断だけで復元失敗と判断しない。
- 通知が許可されていなくてもUIに問題を表示。Activityの説明ダイアログからのみ権限要求。

| Release lint | エラー0、警告11 |
| 最終差分確認 | 空白エラーなし |

警告11件は既存のhidden API reflectionと依存バージョン更新案内。
API26〜33のタイルActivity起動のみ、API34の新APIが存在しないため旧APIを使用。
その分岐のlint誤検出は理由をコメントした局所的な抑制で対処し、API34以上ではPendingIntent版を使う。

追加テストは実際のEngineと偽のBinder/保存先を使うRobolectricテスト、および表示・通知判断の単体テスト。
手動ON/OFF・所有者移行・連打・UI/タイル/通知の同時要求・自動再適用防止・記録なしの無書き込み・不正記録・復元失敗と読み戻し不一致・復元中の切断・再接続での通知解消・通知権限なし・起動時の明示復元と手動pending記録・通知IDの維持・サービス終了時の二重復元防止・タイル更新時の退出待ち維持を検証。
既存の一覧変更・同一一覧保存・未知の前面アプリ・対象間移動の回帰テストも通過。

## 実機で未検証の項目と制約

- SystemUIでのタイル追加、表示、ロック解除・解除キャンセル、API26〜33／34以上でのActivity起動。
- 通知Actionからの起動、通知権限許可／拒否、チャネル個別無効化、Activity再生成。
- OEMのバックグラウンド制限、サービス停止・プロセス終了後の実際の再起動タイミング。
- Shizuku実プロセスの停止・Binder death・再起動とAudioSystemのOEM依存の挙動。

アプリやShizukuが終了している間の即時復元は保証できない。保存情報は次回の起動・接続時に確認する。
本作業では実機へのインストール・操作・音の確認は行っていない。
